# Yet Another API Test Tool (YAATT)

YAATT lets you write API tests in simple JSON files. It's designed for developers and QA who crave a lightweight, intuitive, and fast testing workflow.

## Prerequisite

- You must have [Docker](https://docs.docker.com/get-started/get-docker/) installed on your machine.
- You must have a `./tests` folder in your root directory.
- You must be breathing.

## Setup

Build the image

```sh
docker build -t yaatt .
```

...and copy the test schema file in your host machine

```sh
YAATTCID=$(docker create yaatt)
docker cp $YAATTCID:/app/src/schema.json ./test.schema.json
docker rm $YAATTCID
```

ℹ️ The test schema JSON file is necessary for linting purposes only. It is completely optional.

## Add a new test

To generate a new test file, enter command

```sh
docker run -v $(pwd)/tests:/app/tests -t yaatt bun run generate
```

ℹ️ Rename the autogenerated file to something meaningful.

## Run your test files

In your terminal, enter command

```sh
docker run -v $(pwd)/tests:/app/tests -t yaatt bun run start
```

...and to test a single file

```sh
docker run -v $(pwd)/tests:/app/tests -t yaatt bun run start example_test.json
```

...while for dev mode

```sh
docker run -v $(pwd)/tests:/app/tests -t yaatt bun run dev

```

...and to test single file in dev mode

```sh
docker run -v $(pwd)/tests:/app/tests -t yaatt bun run dev example_test.json
```

ℹ️ Dev mode automatically re-runs your tests on file changes.


## Test file

A test will typically look like this.

```json
{
  "$schema": "./test.schema.json",
  "name": "A sample test specification",
  "description": "This is a sample test specification.",
  "requests": {
    "get_products": {
      "method": "get",
      "url": "https://dummyjson.com/products/3",
      "headers": {
        "Content-Type": "application/json"
      }
    },
    "create_post": {
      "method": "post",
      "url": "https://dummyjson.com/posts/add",
      "headers": {
        "Content-Type": "application/json"
      },
      "body": {
        "title": "{{get_products.meta.qrCode}}"
      }
    }
  },
  "assertions": [
    {
      "type": "is_equals",
      "property": "get_products.id",
      "value": 3
    }
  ]
}
```

### Test Result

Executing tests will produce result like so;

```sh
📄 Test Suite:    A sample test specification
📂 Source File:   example_test.json

=======> Sending API requests <=======

```

## Using environment variables
You can reference environment variables in your test files by using the `env` directive. This allows you to keep environment-specific values (such as URLs or API keys) out of your test code.

Let’s say you’ve defined an environment variable called DUMMY_API_URL and want to reference it in a test file, you can do it like so;

```json
{
  "$schema": "./test.schema.json",
  "name": "A sample test specification",
  "description": "This is a sample test specification.",
  "requests": {
    "get_products": {
      "method": "get",
      "url": "{{env:DUMMY_API_URL}}/products/3",
      "headers": {
        "Content-Type": "application/json"
      }
    },
    "create_post": {
      "method": "post",
      "url": "{{env:DUMMY_API_URL}}/posts/add",
      "headers": {
        "Content-Type": "application/json"
      },
      "body": {
        "title": "{{get_products.meta.qrCode}}"
      }
    }
  },
  "assertions": [
    {
      "type": "is_equals",
      "property": "get_products.id",
      "value": 3
    }
  ]
}
```

ℹ️ Test files must go in the `./tests/` folder.

## Concepts
Below are some of the concepts you should know.

#### `requests`

You can define any number of HTTP requests. Each request has;

- a unique identifier (e.g., `get_products`)
- a HTTP `method`
- a `url`
- `headers` (optional)
- `body` (optional)
- `query` (optional)

```json
{
    "method": "get",
    "url": "https://dummyjson.com/products/3",
    "headers": {
    "Content-Type": "application/json"
    },
    "body": {},
    "query": {}
}
```

#### `assertions`

Each assertion includes;

- `type` - the assertion to perform
- `property` — the response property to check
- `value` — the expected value

The below assertion for example asserts that `id` from the response of `get_products` request is _equals_ to 3.

```json
{
  "type": "is_equals",
  "property": "get_products.id",
  "value": 3
}
```
